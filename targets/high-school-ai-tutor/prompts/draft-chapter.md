# 起草 chapter.yaml

你在起草一章的唯一真相源。格式由流水线保证，你只做教学判断。拿不准的节点不要写。

## 版权红线

- 定义必须转述，禁止逐字摘录课文。
- 例题自编，并在 example 里让人能看出这是自编例子。生成器会在学习页标「示例题非教材原题」。
- 不搬插图，schema 里没有原文字段，也不要自造原文、课文摘录字段。
- source 只写页码或课标位置，例如 `{textbook: P36-38, curriculum: 主题2}`。
- 争议别名不入库，留在 `work/raw/` 给反馈环收编。

## 边

- 实线只写在 `edges`，标签只有 `直接前置` 或 `同章衔接`。
- 一个节点最多一条直接前置，不要把整条前置闭包写进去。
- 虚线只写在 `combo`，标签只有 `常考组合`，可以指向他章已经入库的节点，或本章 `later` 里的灰占位。
- 端点必须真实存在。悬空边会被 scaffold 拒绝；下游三道机检看不见这种边。

## 节点

- `id` 全库唯一，英文蛇形。
- `display` 是正典显示名，也是学习页状态标签里的名字。
- `aliases` 科目内唯一。
- `type` 只能是 `concept`、`skill`、`experiment`。
- `l1` 对应课标「了解 / 知道 / 举例」，`l2` 对应「说明 / 判断 / 应用」，`l3` 是延伸。没有把握就写「待补录：延伸不在本节点展开」。
- `example`、`pitfall`、`confusion` 可以空着，生成器会写成「（待补录：……）」。

## 交给审阅的人

全表看一遍前置、超纲、实验遗漏和别名。再抽 3 条边，在起草会话里自证「为什么是直接前置」，把这 3 条深审。如实记下审阅耗时。

## 顺序

- 目标侧 topo 对同层平局按 id 字母序排序（graph.py 的 ready.sort()）。
  yaml 里 sections[].nodes[] 的数组顺序就是教学顺序，整章图也按它渲染。
- 起草时给 id 选词，尽量让同层节点的字母序与教学顺序一致；
  做不到时接受 scaffold 的 WARN——学习顺序仍有直接前置边兜底，只是同层并列时会按字母序播报。

## 依据核查与疑问清单（每章必做，2026-09-27 起生效）

- 交付前，把每个节点的 l1/l2/example/pitfall/confusion 里的关键表述，
  到 `work/raw/<书>/chapters/` 提取文本和课标拼接文本里搜一遍：
  命中的才可写成结论；命中不了的属于教辅延伸或记忆性内容，
  要么删掉，要么明示"教材图解/常见考法延伸"。
- 交付时必须附「疑问与取舍」清单：哪些点拿不准、哪些口径教材与教辅不一致、
  哪些内容因无依据被删。没有疑问也要显式写"本章无疑问"及核查范围。
  第一章有疑问环节质量才立住，第二章跳过这一步就漏了三处错——此环节不可省。
